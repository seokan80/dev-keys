## 맡긴 뒤의 순서

에이전트는 부탁한 것보다 많이 바꾸는 일이 잦다 — 디버그 로그, 고치다 만 코드, 메모 파일, 상관없는 포맷 변경. **커밋되는 것은 내가 고른 것만** 이 되게 한다.

| 단계           | 명령                                                        |
| -------------- | ----------------------------------------------------------- |
| 훑기           | `git status --short` · `git diff --stat`                    |
| 골라 담기      | `git add -p <파일>`                                         |
| 커밋될 것 읽기 | `git diff --staged`                                         |
| 그것만 시험    | `git stash push --keep-index -u` → 테스트 → `git stash pop` |
| 나머지 버리기  | `git restore -p <파일>` · 새 파일은 `git clean -n` → `-f`   |
| 커밋           | `git commit -m "제목" -m "본문"` (또는 `git commit -v`)     |

## git add -p 의 답

| 답        | 뜻                                                                              |
| --------- | ------------------------------------------------------------------------------- |
| `y`       | 이 덩어리를 담는다                                                              |
| `n`       | 담지 않는다                                                                     |
| `s`       | 더 잘게 나눈다 — 떨어진 변경이 한 덩어리로 묶였을 때 (나눌 수 있을 때만 보인다) |
| `e`       | 덩어리를 직접 고쳐서 담는다                                                     |
| `a` / `d` | 이 파일의 나머지를 모두 담는다 / 모두 건너뛴다                                  |
| `q`       | 그만 (지금까지 고른 것은 남는다)                                                |
| `?`       | 도움말                                                                          |

같은 방식으로 **버리기**는 `git restore -p`, **스테이징에서 내리기**는 `git restore --staged -p`. 덩어리마다 물어보니 한 파일 안에서도 필요한 것만 남길 수 있다.

## 스테이징한 것만 시험하기

`git stash push --keep-index -u` 는 스테이징하지 않은 변경과 새 파일을 잠시 치우고, **스테이징한 것만 작업 트리에 남긴다.** 이 상태로 테스트를 돌리면 "커밋될 코드"를 시험하는 셈이다. 에이전트가 남긴 다른 파일 덕에 우연히 통과하는 일을 막는다. 끝나면 `git stash pop`.

## 커밋 메시지는 검토한 사람이

- `-m` 을 두 번 쓰면 첫째는 제목, 둘째는 본문이 된다
- `git commit -v` 는 메시지 편집기 아래에 커밋될 diff 를 보여 준다 — 쓰면서 마지막으로 한 번 더 본다
- 주제가 둘이면 `add -p` 로 나눠 커밋 둘로. 나중에 되돌리기(`revert`) · 찾기(`bisect`)가 쉬워진다

## 최신 Git

- **`P` 답** — 최근 버전의 `add -p` 에는 덩어리를 페이저로 보는 `P` 가 있다. 덩어리가 길어 화면을 넘칠 때
- **2.35 `git stash push --staged`** — 반대로 스테이징한 것만 치운다
- **2.23 `git restore`** — 예전 `git checkout -p` · `git reset -p` 가 하던 골라 버리기 · 내리기를 맡는다

## AI 에이전트와 쓸 때

- **부탁한 범위와 `diff --stat` 을 견준다.** 상관없는 파일이 바뀌었으면 그것부터 본다
- 자주 섞여 들어오는 것: 디버그 출력, 주석 처리한 코드, 하드코딩한 키 · 주소, lockfile 변경, 포맷만 바뀐 줄
- 에이전트가 직접 커밋하게 해도, 합치기 전 `git show` 나 PR diff 를 사람이 읽는다 — **`git diff --staged` 가 마지막 관문** 이다
- 버리기(`restore -p`, `clean -f`)는 되돌릴 수 없다. 망설여지면 버리지 말고 `git stash` 로 치워 둔다
