# grep으로 로그 찾기

API와 worker 로그에서 릴리스 전에 확인할 오류를 찾는다. `app.log`에는 ERROR가 2줄, WARN이 1줄 있다. FATAL은 없다. 각 세트는 새 초기 상태에서 시작한다.

## 찾는 내용과 보여 주는 방식

| 옵션                     | 뜻                                         |
| ------------------------ | ------------------------------------------ |
| `-n`                     | 줄 번호 표시                               |
| `-i`                     | 대소문자 무시                              |
| `-v`                     | 일치하지 않는 줄                           |
| `-c`                     | 일치한 줄의 수                             |
| `-F`                     | 정규식 대신 고정 문자열                    |
| `-E`                     | 확장 정규식                                |
| `-A 1` / `-B 1` / `-C 1` | 뒤 / 앞 / 앞뒤 한 줄의 문맥                |
| `-l` / `-L`              | 일치한 파일 / 일치하는 줄이 없는 파일 이름 |
| `-q`                     | 출력 없이 종료 상태로만 알림               |
| `-r`                     | 디렉터리 아래도 검색                       |

`-c`는 일치 횟수가 아니라 **일치한 줄 수**다. `-l`은 소문자 L이고 숫자 1이 아니다. 대문자 `-L`과도 구분한다.

## 패턴 구분하기

`grep -E "WARN|ERROR"`의 따옴표 안 `|`는 정규식의 선택 연산자다. Shell 파이프가 아니다. `^INFO`는 INFO로 시작하는 줄, `200$`는 200으로 끝나는 줄을 찾는다. 경로나 기호를 글자 그대로 찾으려면 `-F`가 유용하다.

문맥 출력에서 일치한 줄은 `번호:내용`, 문맥 줄은 `번호-내용`으로 구분된다. 재귀 검색 예시는 도구의 탐색 순서에 의존하지 않도록 `| sort`로 정렬했다. 파이프는 6번째 세트에서 이어서 배운다.

## 아무 출력이 없을 때

`grep -q "ERROR" project/logs/app.log`는 출력 없이 상태 0이다. `grep -q "FATAL" project/logs/app.log`는 출력 없이 상태 1이다. 바로 뒤에서 없는 missing.log를 읽으면 -q여도 오류 메시지가 나오고 상태는 2다. 화면 오른쪽 명령 아래의 종료 상태를 함께 확인한다.

GNU grep의 일반적인 상태는 0이면 일치, 1이면 일치 없음, 2이면 오류다. 따라서 1을 파일 읽기 오류라고 설명하거나, 모든 비영 상태를 무조건 일치 없음이라고 해석하면 안 된다. `-q`는 일치를 찾으면 다른 오류가 있어도 0을 돌려줄 수 있으므로 이 표만으로 모든 입력 파일의 정상 처리를 보증하지 않는다.
